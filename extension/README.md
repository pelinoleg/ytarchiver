# YT Archiver — расширение для Chrome

Личное расширение (Manifest V3): на странице YouTube жмёшь иконку и можешь
**скачать открытое видео** или **подписаться на канал** — прямо на свой
YT Archiver сервер, с теми же опциями, что и в веб-интерфейсе.

## Возможности

- **Watch-страница** → карточка «Скачать это видео» (качество, «это музыка»)
  плюс свёрнутые карточки подписки на канал и (если играет из плейлиста) на плейлист.
- **Страница канала** (`/@handle`, `/channel/UC…`, `/c/…`, `/user/…`) →
  карточка «Подписаться на канал»: политика (Only new / Last N / 7d…1y / all),
  качество, папка (с созданием новой), retention, «Показывать на Home».
- **Страница плейлиста** (`/playlist?list=…`) → карточка «Подписаться на плейлист»
  (качество, «это музыка»). Миксы `RD…` и приватные `WL`/`LL` пропускаются.
- **Анти-дубли**: расширение спрашивает сервер и показывает значок, если видео уже
  скачано / в очереди, или если на канал/плейлист уже подписаны — кнопка блокируется.
- Внизу попапа — индикатор связи с сервером (зелёный = `/api/stats` отвечает).
- Адрес сервера задаётся в настройках, по умолчанию `http://pi5.local:8080`
  (у тебя сейчас `http://pi5.local:8081`).

## Установка

1. Chrome → `chrome://extensions`
2. Включи **Developer mode** (правый верхний угол).
3. **Load unpacked** → выбери папку `extension/`.
4. Открой настройки расширения (иконка ⚙ в попапе или
   `chrome://extensions` → Details → Extension options) и при необходимости
   поменяй адрес сервера. Кнопка «Проверить» пингует `/api/stats`.

Готово — открой любое видео/канал на YouTube и нажми иконку.

## Как это работает

- Контекст страницы читается через `chrome.scripting.executeScript`
  (world `MAIN`) из `ytInitialPlayerResponse` / `ytInitialData` с запасными
  DOM-селекторами — video id, channel id, название.
- Запросы идут на бэкенд:
  - видео → `POST /api/videos/download` `{url, quality, is_music}`
  - канал → `POST /api/channels` `{url, download_policy, quality,
    retention_days, show_on_home, folder_id, latest_count}`
  - папки → `GET/POST /api/channel-folders`
- Сервер уже отдаёт `Access-Control-Allow-Origin: *` (CORS в `backend/main.py`),
  так что fetch из расширения работает без дополнительной настройки.

## Заметки

- Сервер по HTTP в локалке — это нормально: попап расширения сам по себе
  secure-context, а `http://*/*` есть в `host_permissions`.
- Если сервер переехал на другой адрес/порт — поменяй его в настройках,
  пересобирать ничего не нужно.
